## 核心观点

家庭网络优化优先顺序应是：电源和散热稳定、拓扑简单、无线信道和频宽合理、网关/NAT/DNS 路径清楚，再考虑 OpenWrt 插件、分流、多 WAN、流控等高级玩法。

很多卡顿、断流和延迟波动不是带宽不足，而是来自多层 NAT、无线干扰、过宽频宽、软路由承担过多交换流量、DNS/代理链路套娃、后台 P2P 上传、节能降频或不稳定驱动。

## 硬件与物理层

- 设备不要叠放，路由器、光猫、高速网卡和无线芯片都要保证散热；路由器架空通常能明显降温。
- 电源要足功率、低纹波，劣质或虚标 DC 电源会影响网口稳定和 Wi-Fi 发射表现。
- 网线、水晶头、光纤接头要认真处理，潮湿、接触不良和光衰偏高都会造成隐性故障。
- 光纤光衰建议控制在运营商允许范围内，超过临界值容易掉线；接头和熔接质量可能带来数 dB 损耗。
- USB 3.0 可能干扰 2.4 GHz Wi-Fi，可关闭 USB 3.0 模式或做屏蔽处理。
- 无线鼠标、蓝牙耳机等 2.4 GHz 外设也可能干扰 Wi-Fi，接收器可用延长线移远。

## 拓扑与网关

- 家庭网络尽量保持同一层交换、同一网段，避免多层 WAN 级联和多层 NAT。
- 只有在确实需要隔离时才做多网段；日常家庭共享和管理场景，固定 IP 或 DHCP 静态租约更方便。
- 整网只保留一个 DHCP 服务，通常由主路由负责，避免多个 DHCP 服务互相抢答。
- 光猫能桥接时优先桥接到性能更好的路由器，但部分地区可能因光猫或 ISP 限制导致桥接后掉速，需要实测。
- 内部路由器如果只做 AP/交换用途，可关闭不必要的防火墙，减少转发开销。
- 旁路由本质是旁路网关，适合在保留主路由原厂无线性能的同时扩展 OpenWrt 服务；需要代理或广告过滤的终端再指向旁路由网关或 DNS。
- 软路由不适合承担大量 LAN 口交换负载，内网高吞吐设备建议接硬交换机或硬路由交换芯片。

## Wi-Fi 调优

- 频宽在满足吞吐需求的前提下尽量低：2.4 GHz 通常使用 20 MHz，5 GHz 可先从 40 MHz 起步。
- 频宽越高，邻频干扰越多，延迟也更容易抖动；游戏和稳定性优先时不要盲目追求 80/160 MHz。
- 不使用的 2.4 GHz 或 5 GHz 射频可以关闭，减少发热和自干扰。
- 使用 Wi-Fi 分析工具选择占用少、邻频干扰弱的固定信道。
- 多 AP 覆盖优先使用 Mesh 或合理布点，不要过密覆盖；可降低功率，让终端更容易落到最近 AP。
- 面板 AP 外观整洁但性能通常受限，家庭场景要谨慎选择。
- Wi-Fi 6 的 OFDMA、BSS Coloring 等能力对抗干扰和降低延迟有帮助；中继场景也优先考虑 Wi-Fi 6。
- 无线中继不要单频收发复用，最好接收和发射分频；5 GHz 中继通常比 2.4 GHz 延迟更低。
- 老设备兼容性差时，可先降低信道/频宽、关闭无线节能，再尝试关闭 Wi-Fi 6。
- 加密优先用 WPA2-PSK + AES；游戏优先时可按设备支持情况评估突发模式等队列选项。

## OpenWrt 使用原则

- 不熟悉的插件和服务不要随意删除；更稳妥的做法是先禁用自启动。
- 不要频繁刷最新固件。没有明确功能需求时，稳定运行比追新更重要。
- 软路由不建议用 U 盘作为系统盘，长期运行容易文件损坏或坏块。
- CPU 不建议长期动态节能到过低频率，网络响应可能因降频/升频切换产生波动。
- 定时重启有实际意义，尤其是普通内存、日志和临时文件长期增长的家庭设备。
- Netdata、NLBW 等实时监控会持续占用 CPU，并可能通过抓包统计影响性能；平时不用可以停用或删除。
- SSH 日常不用时建议关闭，或至少做好密钥、口令和访问控制。
- 路由器系统时间必须准确，NTP 校时应开启，否则可能影响 HTTPS/SSL 校验。

## 加速、QoS 与流控

- 使用 QoS/流控时，软硬件加速通常需要关闭，否则队列控制可能失效。
- SFE、flow offload、TurboACC 等加速能降低 CPU 占用、提高转发率，但在部分环境会引发卡顿或断流，需要按场景取舍。
- MTK 硬路由开启硬件 NAT 和 Wi-Fi 加速后，不建议叠加 SFE/offload、CPU 负载均衡、BBR 等软件加速。
- 防火墙或加速模块里的 Full Cone NAT 选项通常有利于游戏、P2P 和视频连接，可按安全边界评估开启。
- 去广告规则不要贪多，重复合并规则会增加过滤成本；CPU 性能较弱的设备要控制规则规模。

## DNS 与分流

- DNS 链路要画清楚：本地 DNS、上游 DNS、代理分流 DNS、远程 DNS 各自负责什么，避免套娃和泄露。
- 不建议只返回“最快单一 IP”的解析模式，因为视频和下载可能依赖多点传输；游戏场景则可更重视最低延迟。
- 多个 DNS 上游可能解析出更多可用 IP，也可能绕开部分运营商 DNS 污染。
- SmartDNS 适合测速和多 IP 返回；MosDNS 适合分流、防泄漏和去广告；AdGuard Home 适合可视化广告过滤和规则管理。
- 浏览器内置安全 DNS/DoH 可能绕开路由器 DNS 策略，排查 DNS 泄露时应关闭。
- 代理或 Mihomo 类分流不仅要做区域分流，还要按协议和设备分流；国内常用站点需要验证是否被错误绕到海外。
- 使用代理前如不需要 IPv6，应关闭相关 IPv6 解析和过滤遗漏，避免 IPv6 路径绕过策略。

## NAT、多 WAN 与 P2P

- 家庭多拨、多 WAN 对下载/上传和备线有价值，但 OpenWrt 上多路策略维护成本高，端口和应用策略不完整时容易波动。
- 多 WAN 分流和流控如果是核心需求，原帖更倾向使用爱快，因为其策略库和分流库更成熟。
- P2P 下载、直播软件、电视盒子和网盘客户端可能在后台持续上传，要及时关闭或限速，避免占满上行。
- UPnP 对家庭游戏、下载和 P2P 连接数有帮助，但应结合安全边界使用。
- NAT 类型会影响游戏、P2P 和视频传输。排障时可用 STUN 工具测试 NAT1/Full Cone、受限锥型、端口受限锥型和对称 NAT。
- 光猫 TR069 不建议直接删除。更稳妥的做法是让 ITMS 地址失效，在运营商需要重新下发配置时再恢复。

## 设备选型

- 刷 OpenWrt 的硬路由要关注无线驱动质量。MTK 闭源驱动通常能保证较好的 Wi-Fi 表现，但和部分 Apple 设备兼容性可能不如高通。
- 官方 OpenWrt 或第三方开源无线驱动在部分硬路由上可能信号、稳定性不如原厂固件。
- 只把 OpenWrt 当路由和分流设备时，ARM 软路由的性能、体积、功耗和散热可能比低功耗 x86 更适合。
- x86 固件和虚拟化生态更丰富，也更适合 All-in-One，但套娃越多，性能损耗和稳定性风险越高。
- 高速网卡发热明显，2.5G/10G 设备要关注散热；部分 Intel I225/I226 批次存在断流反馈，Realtek RTL8125 在不少家庭场景更稳。
- 新一代 ARM 路由器相比 MT7620/MT7621 等老 MIPS 平台有明显性能提升；涉及代理加密时要关注 AES/专用网络加速能力。
- 买二手路由器要考虑射频芯片和功放老化，长期开机设备的 Wi-Fi 性能可能已经衰减。

## 排障清单

- 先确认物理层：电源、散热、网线、水晶头、光衰、网卡温度。
- 再看拓扑：是否多层 NAT、多个 DHCP、软路由承担过多 LAN 交换、自动 WAN/LAN 误判。
- 再看 Wi-Fi：信道、频宽、覆盖密度、节能选项、USB 3.0/蓝牙干扰、老终端兼容。
- 再看系统：CPU 频率、加速开关、QoS 是否冲突、监控插件是否持续抓包。
- 再看 DNS/代理：浏览器 DoH、IPv6、国内站点是否错误代理、DNS 是否泄露或套娃。
- 最后看应用：P2P/直播/网盘是否占用上行，UPnP/NAT 类型是否影响连接建立。

## 对本仓库配置的启发

- Full / Core 模板的 DNS 设计应继续保持链路清晰，避免把国内解析、海外默认解析、代理节点解析混在一起。
- 分流规则应优先表达明确意图，避免过宽规则导致国内常用站点绕路。
- Nano 模板保持轻量是合理的：弱设备上过多 DNS、去广告、监控和复杂分流会放大性能问题。
- 文档和模板应提示用户关闭浏览器安全 DNS、自定义 DNS 覆写、客户端附加上游 DNS 等容易绕开模板策略的选项。
- 家庭路由模板不应鼓励盲目开启所有加速和过滤功能，应让用户按硬件性能和网络目标取舍。
